# Internationalization (i18n)

Forge's `i18n` package is Rails I18n for Go, in the standard-library core:
translations in `config/locales`, dotted keys, `%{name}` interpolation, CLDR
plural forms, a locale per request, and localized numbers and dates. The
decisions, limits and the Forge-Rust port are in
[ADR 0042](adr/0042-internationalization.md).

## Quick start

```sh
forge new shop --locale pt-BR       # en.json and pt-BR.json; pt-BR is the default locale
cd shop
forge dev
curl -H 'Accept-Language: en' http://127.0.0.1:8080/      # "Welcome to shop"
curl -H 'Accept-Language: pt-BR' http://127.0.0.1:8080/   # "Bem-vindo ao shop"
forge i18n check                    # every locale complete?
```

`--locale` accepts `en` (the default), `es` and `pt-BR`: Forge ships the
text of the generated pages in those languages. Add any other locale by
copying a file (below).

## Translation files

```text
config/locales/locales.go               embeds *.json; DefaultLocale; New(cfg, logger)
config/locales/en.json                  layout, welcome page, number and date formats
config/locales/pt-BR.json               the same keys in Brazilian Portuguese
config/locales/authentication.en.json   sign-in, two-factor and password-reset pages (PostgreSQL)
config/locales/posts.en.json            added by `forge generate scaffold post ...`
```

A file is `LOCALE.json` or `SCOPE.LOCALE.json`. It holds one object whose
only key is the locale, as in a Rails YAML file:

```json
{
  "en": {
    "users": {
      "welcome": "Welcome back, %{name}!",
      "intro_html": "<strong>%{name}</strong> joined %{team}",
      "inbox": {
        "zero": "No messages",
        "one": "%{count} message",
        "other": "%{count} messages"
      }
    }
  }
}
```

- Keys are dotted paths (`users.welcome`); segments use letters, digits,
  `_` and `-`.
- The files of a locale are merged. A key defined twice, in one file or
  across files, stops the application at startup, naming both files.
- Locales are `language[-Script][-REGION]`: `en`, `pt-BR`, `zh-Hant-TW`,
  `es-419`. Name files canonically: `pt-br.json` is refused with the right
  name. The available locales are the files present.
- Limits: 1 MiB per file, 512 files, 16 levels, 50,000 keys per locale.
- Converting a Rails file: `yq -o json config/locales/fr.yml > fr.json`.

### Adding a locale

```sh
cp config/locales/en.json config/locales/fr.json
cp config/locales/authentication.en.json config/locales/authentication.fr.json   # PostgreSQL applications
# translate the values and rename the top-level key "en" to "fr" in both files
forge i18n check
```

## Using translations

In templates (`app/views`):

```gohtml
<html lang="{{locale}}">
<h1>{{t "users.welcome" "name" .User.Name}}</h1>
<p>{{t "users.intro_html" "name" .User.Name "team" .Team}}</p>
<p>{{t "users.inbox" "count" .Unread}}</p>
<p>{{l .CreatedAt "short"}} · {{l .Birthday "date.formats.long"}} · {{number .Total 2}}</p>
```

In Go (handlers, flash messages):

```go
web.SetFlash(w, r, web.FlashNotice, i18n.T(r.Context(), "posts.flash.created"))
message := i18n.T(r.Context(), "throttled.sign_in", "count", minutes)
```

Arguments are name/value pairs. `count` also selects the plural form.

Outside a request (jobs, mailers), bind a locale yourself:

```go
ctx = i18n.NewContext(ctx, translator, user.Locale)
subject := i18n.T(ctx, "mailers.welcome.subject", "name", user.Name)
```

### Escaping

- `t` returns plain text: `html/template` escapes it, and every argument in
  it, for the context it lands in (element, attribute, URL).
- Keys ending in `_html` (or named `html`) are trusted markup from your own
  files: the text is not escaped, every argument is HTML-escaped unless it
  is `template.HTML`. Never build such a key from request input, and never
  interpolate URLs from users into an `href` inside one: the value is
  escaped, not checked as a URL. Put links in the template instead.
- `i18n.T` returns the text as written (the markup of `_html` keys with
  escaped arguments); `i18n.HTML` returns `template.HTML`, escaping plain
  keys.

### Plural forms

Plural objects use the CLDR categories `zero`, `one`, `two`, `few`, `many`
and `other` (`other` is required). Forge picks the category with the CLDR
rule of the locale the text came from, for integer and decimal counts:

| Locales | Forms to write |
| ------- | -------------- |
| en, de, nl, sv, nb, fi, et, es, it, pt-PT, tr, el, hu | `one`, `other` |
| pt, pt-BR, fr (0 and 1 are `one`) | `one`, `other` |
| ru, uk, pl | `one`, `few`, `many` (and `other` for fractions) |
| cs, sk | `one`, `few`, `other` (`many` for fractions) |
| ar | `zero`, `one`, `two`, `few`, `many`, `other` |
| he | `one`, `two`, `other` |
| ja, zh, ko, vi, th, id, ms | `other` |

An explicit `zero` form is used for 0 in every language; without a `count`
argument a plural key gives its `other` form. A form the rule
chooses but the file lacks falls back to `other` (Spanish, French, Italian
and Portuguese `many` is only for whole millions). Other languages use
`other` until you add a rule:

```go
translator, err := i18n.Load(files, i18n.Options{
	DefaultLocale: "en",
	PluralRules: map[string]i18n.PluralRule{
		// CLDR "cy" (Welsh), from https://cldr.unicode.org/index/cldr-spec/plural-rules
		"cy": func(o i18n.Operands) i18n.Category {
			if o.V != 0 {
				return i18n.Other
			}
			switch o.I {
			case 0:
				return i18n.Zero
			case 1:
				return i18n.One
			case 2:
				return i18n.Two
			case 3:
				return i18n.Few
			case 6:
				return i18n.Many
			}
			return i18n.Other
		},
	},
})
```

`Operands` are CLDR's n (absolute value), i (integer digits) and v (number
of visible fraction digits).

### Numbers and dates

`number` and `l` read Rails' keys from the locale (then its parents, the
default locale, then built-in English):

```json
{"pt-BR": {
  "number": {"format": {"separator": ",", "delimiter": ".", "precision": 2}},
  "date": {"formats": {"long": "%-d de %B de %Y"},
           "month_names": [null, "janeiro", "fevereiro", "março", "abril", "maio", "junho",
                           "julho", "agosto", "setembro", "outubro", "novembro", "dezembro"]},
  "time": {"formats": {"short": "%d/%m %H:%M"}, "am": "", "pm": ""}
}}
```

`l .Time "short"` uses `time.formats.short`; a name with a dot is a full key.
Directives: `%Y %y %m %d %e %j %H %I %M %S %p %P %A %a %B %b %z %Z %%`; `%-d`
drops the padding. `number 1234.5` is `1.234,50` in pt-BR; integers get no
decimals unless a precision is given.

## Choosing the locale

`translator.Middleware(i18n.NegotiationOptions{...})` (installed first by
`useBrowserPipeline`) picks, in order:

1. the first path segment, with `PathPrefix: true` (`/pt-BR/posts` is served
   by `GET /posts`; the segment must be an available locale);
2. a query parameter, with `Param: "locale"` (`?locale=pt-BR`);
3. the `locale` cookie (`Cookie` renames it);
4. `Accept-Language`, by quality (`q=0` excluded, `*` means the default);
5. the default locale: `FORGE_I18N_DEFAULT_LOCALE`, else
   `locales.DefaultLocale` (`forge new --locale`), else `en`.

A requested locale matches itself, else its parent (`pt-PT` → `pt`), else a
variant of its language (`pt` → `pt-BR`). Invalid names are ignored, so a
header, cookie or URL can never name a file. Pages rendered by the views
renderer carry `Content-Language` and `Vary: Accept-Language, Cookie`;
handlers that write translated text themselves call
`i18n.SetHeaders(w, r.Context())` (the welcome page does). The middleware
sets no headers, so digested assets and JSON stay cacheable.

A language switcher stores the choice:

```go
func switchLocale(translator *i18n.Translator) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		if err := translator.SetCookie(w, "", r.FormValue("locale")); err != nil {
			web.Error(w, r, fault.New("invalid_locale", "unknown locale", fault.CategoryInvalid, 0))
			return
		}
		_ = web.Redirect(w, "/")
	}
}
```

The cookie is `Secure`, `HttpOnly`, `SameSite=Lax`, for a year. Register the
route behind the CSRF middleware like any form.

```sh
FORGE_I18N_DEFAULT_LOCALE=pt-BR forge dev
curl -i -H 'Accept-Language: fr-CA, pt;q=0.8' http://127.0.0.1:8080/ | grep Content-Language   # pt-BR
curl -i --cookie 'locale=en' http://127.0.0.1:8080/ | grep Content-Language                      # en
```

## Missing translations

| Environment | Missing key shows | Then |
| ----------- | ----------------- | ---- |
| development, test | `translation missing: pt-BR.posts.index.title` | warning logged once |
| staging, production | the default locale's text, else the key humanized ("Title") | warning logged once |

The locale's parents are always tried first (`pt-BR` → `pt`). Nothing
panics: an unknown key, a missing `%{name}` value (left as written) or
malformed arguments are logged; `t` with an odd number of arguments stops
`views.Load`. Generated tests fail when a page shows `translation missing`.

## `forge i18n check`

```sh
forge i18n check          # human report; exit 1 when a locale lacks keys or plural forms
forge i18n check --json   # schema-versioned report for CI and agents
```

```text
config/locales: en, pt-BR; 82 keys, 64 referenced in templates and Go code

en: complete

pt-BR: 2 missing
  posts.index.title
  posts.flash.created

unused: 1 (no literal t "KEY" or i18n.T(ctx, "KEY") found; keys built at runtime are not detected)
  users.old_banner
```

It compares every locale with the keys of all the others and with the
literal keys in `t "KEY"` (templates) and `i18n.T(ctx, "KEY")`,
`i18n.HTML(ctx, "KEY")`, `translator.Translate(locale, "KEY")` (Go, tests
excluded), checks the plural forms each locale's rule needs, and lists keys
nothing references. Keys built at runtime are not seen; `date.*`, `time.*`
and `number.*` are data and never reported unused. It reads files only and
never runs application code.

## Generators

| Command | Translations |
| ------- | ------------ |
| `forge new NAME [--locale es\|pt-BR]` | `config/locales` with the layout, welcome page and (PostgreSQL) authentication pages |
| `forge generate scaffold post ...` | `config/locales/posts.en.json`; pages use `t`, flash messages `i18n.T`. Translate it into `posts.LOCALE.json` |
| `forge generate authentication` | `authentication.en.json`, plus `authentication.es.json`/`pt-BR.json` when those locales exist |
| `forge generate view`, `controller`, `scaffold`, `authentication` | add `config/locales` to an application that lacks it |
| `forge destroy scaffold post ...` | removes `posts.en.json` unless edited |

Applications created before i18n: run any of these generators to get
`config/locales`, then add to `app/bootstrap/bootstrap.go`:

```go
translator, err := locales.New(app.Config(), app.Logger())   // in Configure; pass it to routes
translations, err := translator.Middleware(i18n.NegotiationOptions{})
// first in useBrowserPipeline: []func(http.Handler) http.Handler{translations, web.MethodOverride, ...}
renderer, err := views.New(views.WithI18n(translator))
```

Controller and mailer stubs, framework validation messages and the
scaffold's Yes/No and time values are still English: see the follow-ups in
ADR 0042.
